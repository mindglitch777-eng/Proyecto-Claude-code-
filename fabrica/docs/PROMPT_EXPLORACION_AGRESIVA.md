# Prompt vivo — "Capa de exploración agresiva de skills, Remotion, MCP y arsenal audiovisual"

**Por qué existe este archivo:** este prompt (de ChatGPT, pegado por el
operador) se venía re-pegando de memoria ronda tras ronda porque el
resumen automático de la conversación (compactación por límite de
contexto) solo guarda un PARAFRASEO de las partes que se usaron, no el
texto literal completo -- así que después de 2-3 compactaciones ya no
quedaba registro exacto de los 31 puntos, solo de ~16. El operador pidió
explícitamente (2026-09-03) un archivo chico que se actualice solo,
en vez de depender de la memoria de la conversación. Este es ese
archivo: vive en el repo (se commitea), no en el chat.

**Regla de uso:** cada vez que se avance en un punto de este prompt, se
actualiza la columna "Estado" de la tabla de abajo y se agrega una
línea a "Historial de actualizaciones" -- no se espera a que termine
toda la ronda. Si en algún momento este archivo dice que algo está
HECHO pero al revisar el código no es así, gana el código, no este
archivo (documentación desactualizada es un bug, se corrige).

## El prompt, texto completo (pegado 2026-09-03, versión con "cambio de comportamiento" explícito)

```
PROMPT — CAPA DE EXPLORACIÓN AGRESIVA DE SKILLS, REMOTION, MCP Y ARSENAL AUDIOVISUAL

IMPORTANTE:
Este pedido NO significa crear otra fábrica paralela ni duplicar sistemas que ya existen.
La fábrica actual ya tiene muchas capas construidas. Tu trabajo ahora es aumentar
drásticamente sus capacidades mediante investigación, descubrimiento, pruebas e
integración inteligente de herramientas externas.

Hasta ahora fuiste demasiado conservador en algunos puntos. Quiero cambiar
explícitamente esa conducta. No quiero que descartes una herramienta simplemente
porque "ya tenemos Remotion", "ya tenemos un editor", "ya tenemos un sistema propio"
o "no parece necesaria". Tampoco quiero que instales basura indiscriminadamente.

Quiero: EXPLORACIÓN AGRESIVA → INSPECCIÓN → PRUEBA → COMPARACIÓN → DECISIÓN →
INTEGRACIÓN → DOCUMENTACIÓN.
La regla es: NO LIMITAR LA EXPLORACIÓN. SÍ LIMITAR LAS INTEGRACIONES INÚTILES.

1. OBJETIVO -- convertir la fábrica en un sistema operativo audiovisual de
   altísimo nivel: maximizar atención, retención, comprensión, impacto, calidad
   visual, ritmo, narrativa, sincronización audiovisual, variedad, identidad de
   marca, capacidad de experimentación, capacidad de aprendizaje, producción
   continua. No asumir que nuestra implementación actual es la mejor posible.

2. CAMBIO DE COMPORTAMIENTO -- ante cada herramienta responder: ¿qué hace?
   ¿qué problema resuelve? ¿qué aporta que no tenemos? ¿qué aporta que
   podríamos hacer mejor? ¿reutilizable? ¿adaptable? ¿inspiración de
   arquitectura? ¿compatible con nuestro stack? ¿costo? ¿restricciones? ¿vale
   integrar/probar/solo referencia? Si no se puede comprobar algo: BLOQUEADO
   — NO CONFIRMADO, nunca inventar.

3. INVESTIGACIÓN DEL ECOSISTEMA REMOTION -- exhaustiva: skills, reglas, docs
   oficiales, templates, ejemplos, repos, componentes, librerías, proyectos de
   comunidad, herramientas para Claude Code, MCP, integraciones, técnicas,
   subtítulos, motion graphics, transiciones, efectos, composición, gráficos,
   charts, mapas, visualización de datos, kinetic typography, sincronización
   con audio, edición por timestamps, partículas, 3D, cámaras, efectos
   cinematográficos, edición documental, edición redes sociales, composición
   avanzada, automatización, render, optimización, QA. No solo las 3 guías
   oficiales ya conocidas -- descubrir TODO lo relevante (sin instalar todo).

4. INVESTIGAR SKILLS DE CLAUDE CODE -- relacionadas con Remotion, video
   editing, motion design, storytelling, short-form video, YouTube, TikTok,
   Instagram, content creation, visual storytelling, subtitles, audio, TTS,
   research, viral content, marketing, sales, digital products, analytics,
   automation, MCP. Proyectos reales de comunidad/GitHub, no lista superficial.

5. INVESTIGAR MCP -- YouTube, TikTok, Instagram, Google Trends, investigación
   de contenido, analytics, búsqueda web, GitHub, Reddit, comunidades,
   investigación de mercado, productos digitales, ventas, automatización,
   archivos, generación multimedia. Prioridad: herramientas que muestren "qué
   contenido funciona REALMENTE" vs. "qué dice alguien que funciona".
   Registrar: nombre, función, costo, límites, autenticación, disponibilidad,
   utilidad, compatibilidad, riesgos, estado.

6. NO DESCARTAR DEMASIADO RÁPIDO -- 5 resultados posibles: INTEGRAR / PROBAR /
   USAR COMO REFERENCIA / DESCARTAR / BLOQUEADO-NO CONFIRMADO. Todo DESCARTAR
   necesita razón concreta.

7. PRUEBAS REALES -- cuando sea gratis y técnicamente posible: instalar
   aislado, ejecutar ejemplo mínimo, comparar con nuestra implementación,
   verificar compatibilidad, medir, documentar. No hace falta integrar de
   inmediato, primero demostrar que sirve.

8. PRESUPUESTO -- $0 hasta la primera venta real. No activar servicios pagos.
   Si algo es excelente pero pago: registrarlo igual (qué hace, cuánto cuesta
   si se confirma, por qué útil, alternativa gratis, si vale dejarlo preparado
   para el futuro) sin volverlo dependencia.

9. CREAR EL "ARSENAL AUDIOVISUAL" -- capa conceptual (buscar si ya existe
   estructura equivalente antes de crear otra). Template fijo por capacidad:
   CAPACIDAD / HERRAMIENTAS / NUESTRA IMPLEMENTACIÓN / MEJOR OPCIÓN ACTUAL /
   ESTADO / EVIDENCIA / COSTO / COMPATIBILIDAD / RIESGO.

10. NO QUIERO SOLO HERRAMIENTAS -- investigar TÉCNICAS aunque no requieran
    librería: composición, ritmo, pacing, transiciones, revelaciones,
    visualización de datos, uso de espacio, movimiento, tipografía, contraste,
    cambios de escala, capas, sonido, silencios, sincronización, storytelling
    visual, edición documental/respuesta directa/educativo/financiero/
    negocios/redes sociales.

11. REFERENCIAS REALES -- videos/proyectos de alta calidad, NO para copiar
    contenido sino para estudiar estructura, edición, ritmo, hook,
    progresión, composición, uso de gráficos, sonido, transiciones,
    identidad, patrones visuales.

12. CONECTARLO CON NUESTROS DIRECTORES -- todo debe poder alimentar Director
    de Retención/Visual/Edición/Audio/Assets, Crítico Audiovisual, Knowledge
    Engine, Decision Engine, Laboratorio. No quedarse solo en un documento.

13. CONECTARLO CON DATOS -- clasificar estrictamente: EVIDENCIA REAL / PATRÓN
    OBSERVADO / BUENA PRÁCTICA / HIPÓTESIS / EXPERIMENTO / RESULTADO REAL /
    CONCLUSIÓN. Nunca convertir popularidad en causalidad.

14. SISTEMA DE COMPARACIÓN -- cuando haya varias alternativas: Opción A/B/C
    (qué hace, ventajas, desventajas, costo, riesgo, compatibilidad,
    evidencia) + RECOMENDACIÓN + DECISIÓN (pendiente operador / automatizable
    / descartada).

15. INTEGRACIÓN INTELIGENTE -- no solo entregar lista: determinar qué entra
    de verdad. Prioridad P0 (imprescindible) / P1 (muy valioso) / P2
    (interesante) / P3 (referencia futura) + qué se puede implementar YA con
    $0.

16. NO DUPLICAR SISTEMAS -- pero "ya existe algo parecido" no significa "no
    investigar": comparar primero, puede que la solución externa sea mejor,
    la nuestra sea mejor, o se puedan combinar.

17. AUDITORÍA DE NUESTRA FÁBRICA -- mientras se investiga, auditar también lo
    propio: capacidades débiles, partes demasiado simples/rígidas, partes que
    dependen de reglas manuales, partes que se beneficiarían de una skill/MCP/
    conocimiento/componente/herramienta, partes que limitan la calidad.
    Encontrar los techos actuales.

18. PRIORIDAD: CALIDAD -- no optimizar solo por "funciona" sino "funciona y
    produce un resultado audiovisual mucho mejor".

19. PRIORIDAD: APRENDIZAJE -- cada investigación deja algo permanente: qué se
    encontró, dónde, qué se comprobó, qué no se pudo comprobar, qué se probó,
    qué funcionó, qué falló, qué se descartó y por qué, qué probar después.

20. AUTONOMÍA -- no preguntar por cada decisión chica. Si es gratis,
    reversible, segura y técnicamente razonable: investigar/probar/documentar
    sin parar. Pedir confirmación solo si: puede generar dinero, es
    irreversible, puede romper sistemas existentes, requiere decisión de
    arquitectura importante, hay licencia no confirmada, o necesita
    credenciales del operador.

21. USAR EL TIEMPO DISPONIBLE -- no apurar por cumplir, pero tampoco
    investigación infinita sin resultados: cuando una línea deja de producir
    información útil, cerrarla y pasar a la siguiente.

22. RESULTADO FINAL -- informe A. Qué investigaste. B. Qué encontraste. C.
    Herramientas/skills/MCP descubiertos. D. Técnicas descubiertas. E. Qué
    probaste. F. Qué funcionó. G. Qué no funcionó. H. Qué integraste. I. Qué
    recomendás integrar. J. Qué dejaste como referencia. K. Qué descartaste y
    por qué. L. Qué quedó bloqueado. M. Qué capacidades nuevas tiene ahora la
    fábrica. N. Qué capacidades siguen faltando. O. Qué deberíamos construir
    después. P. Qué decisiones necesitás del operador.

23. REGLA ESPECIAL SOBRE REMOTION -- "Remotion ya existe" NUNCA es razón para
    terminar la investigación del ecosistema alrededor de Remotion.

24. REGLA ESPECIAL SOBRE CLAUDE CODE -- usarlo como agente de investigación e
    ingeniería, no solo "escribir el código pedido". Si existe una solución/
    herramienta/skill/MCP mejor: proponerla/investigarla. Si la implementación
    propia es mejor: explicar por qué.

25. REGLA ESPECIAL SOBRE EL TECHO -- no poner techo artificial. "Algo
    avanzado" no es "unas pocas funciones más". Diferenciar siempre: LO
    POSIBLE / LO COMPROBADO / LO DISPONIBLE GRATIS / LO EXPERIMENTAL / LO
    FUTURO.

26. ORDEN DE EJECUCIÓN (20 pasos) -- auditar lo existente, mapear capacidades,
    investigar ecosistema Remotion, investigar skills, investigar MCP,
    investigar librerías/repos, investigar técnicas, investigar referencias
    reales, comparar contra la fábrica, identificar gaps, probar herramientas
    gratis relevantes, integrar solo lo que demuestre valor, alimentar
    Knowledge Engine, alimentar Directores, actualizar Decision Engine,
    actualizar memoria, documentar todo, ejecutar todos los tests, verificar
    que nada se rompió, entregar informe final.

27. REGLA DE NO DESTRUIR -- no borrar/romper sistemas existentes. Todo cambio
    importante: reversible, testeado, documentado. Si una integración necesita
    tocar algo importante: explicar riesgo y alternativa primero.

28. REGLA DE PRESUPUESTO -- $0, sin excepciones, sin gastos automáticos, sin
    servicios/suscripciones/APIs pagas. Lo pago excelente se registra para el
    futuro, no se activa.

29. NO QUIERO OTRA CARPETA POR CADA IDEA -- buscar si ya existe un lugar
    correcto antes de crear archivos/carpetas/módulos nuevos. Arquitectura
    limpia, integrar en lo existente cuando corresponda.

30. CRITERIO FINAL -- actuar como ARQUITECTO + INVESTIGADOR + INGENIERO +
    AUDITOR + EXPLORADOR, no como programador que solo implementa lo ya
    imaginado. Buscar lo que no se está viendo. La conclusión de "esto no
    aporta" debe venir DESPUÉS de explorar, no antes.

31. COMENZÁ AHORA -- no pedir confirmación para empezar. Auditar, investigar,
    probar con $0, integrar lo que tenga valor. No inventar resultados ni
    capacidades. No gastar dinero. No romper nada. No duplicar sistemas.
    Informe final: QUÉ TENÍAMOS → QUÉ ENCONTRASTE → QUÉ PROBASTE → QUÉ
    FUNCIONÓ → QUÉ INTEGRASTE → QUÉ DESCARTASTE → QUÉ NOS FALTA → QUÉ PODEMOS
    HACER AHORA.
```
